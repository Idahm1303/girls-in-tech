# Girls in Tech · TUT Faculty of ICT

The Girls in Tech (GiT) web application helps TUT Faculty of ICT students join
the community, complete their profile once, and access member areas.

## Requirements

- Node.js 20.9 or newer
- npm
- PostgreSQL 14 or newer

## Local setup

1. Install dependencies:

   ```bash
   npm install
   ```

2. For Neon, run `neon init` and `neon deploy`; set the pooled
   `DATABASE_URL` and copy the direct `DATABASE_URL_UNPOOLED` value to
   `DIRECT_URL`. For another PostgreSQL host, set `DATABASE_URL` to its runtime
   connection string and `DIRECT_URL` to its direct connection string. Set
   `AUTH_SECRET` to a unique random secret.
3. Generate the Prisma client and apply the database migration:

   ```bash
   npm run db:generate
   npm run db:migrate
   ```

   Prisma loads `.env.local` for database commands. `DATABASE_URL` is used by
   the application for pooled connections; Prisma migrations use `DIRECT_URL`.
4. Load the development sample data:

   ```bash
   # Set GIT_ADMIN_PASSWORD (12 or more characters) before running the seed.
   npm run db:seed
   ```

5. Start the website:

   ```bash
   npm run dev
   ```

   Visit [http://localhost:3000](http://localhost:3000).

## Testing accounts

The 16 completed sample student accounts are `sample.<campus><number>@gmail.com`,
where `<campus>` is `soshanguve`, `emalahleni`, `polokwane`, or `giyane`, and
`<number>` is 1 through 4. All use `ChangeMe123!`. The incomplete-profile
onboarding test account is `incomplete.student@gmail.com` and uses the same
password.

These are development/testing credentials only. Never use them in a deployed
environment. The seeded admin account uses the local `GIT_ADMIN_PASSWORD`.
Seed mentor accounts covering pending, approved, rejected, and needs-information states use
`ChangeMe123!`; the same password is for testing only.

Mentor application email delivery uses Resend. Configure `RESEND_API_KEY`,
`RESEND_FROM_EMAIL`, and `GIT_ADMIN_EMAIL` in the local environment to send
application and decision messages. Mentor profile photos are optional and are
uploaded after a mentor signs in; small images are resized and stored in the
PostgreSQL `StoredFile` table. Do not upload CVs or PDFs.

## Database commands

- `npm run db:generate` regenerates the Prisma client.
- `npm run db:validate` validates the Prisma schema.
- `npm run db:migrate` applies pending development migrations.
- `npm run db:migrate:deploy` applies committed migrations to a deployed
  database such as the Neon production branch.
- `npm run db:seed` inserts development-only sample data and refuses to run
  when `NODE_ENV=production`.
- `npm run db:seed:admin` creates or rotates only the administrator account
  using `GIT_ADMIN_EMAIL`, `GIT_ADMIN_PASSWORD`, and optionally `GIT_ADMIN_NAME`.

## Vercel deployment

1. Import this repository into Vercel and use the default Next.js build command,
   `npm run build`. Prisma Client is generated by both the install and build
   scripts.
2. Add these variables to the Vercel Production environment:
   - `DATABASE_URL`: Neon pooled PostgreSQL URL.
   - `DIRECT_URL`: Neon direct, non-pooled PostgreSQL URL.
   - `AUTH_SECRET`: a unique random secret; do not reuse a development value.
   - `NEXT_PUBLIC_SITE_URL`: the public site URL, including `https://`.
   For Preview deployments, use a separate Neon branch and a separate
   `AUTH_SECRET`; omit `NEXT_PUBLIC_SITE_URL` so the deployment-specific
   `VERCEL_URL` is used.
3. Optional email delivery variables are `RESEND_API_KEY`,
   `RESEND_FROM_EMAIL`, and `GIT_ADMIN_EMAIL`. The first two enable mentor
   emails; `GIT_ADMIN_EMAIL` receives new-application notifications.
4. From a trusted terminal configured with the production `DIRECT_URL`, apply
   schema updates with `npm run db:migrate:deploy`. Create the first admin
   without sample data by setting `GIT_ADMIN_EMAIL` and a private
   `GIT_ADMIN_PASSWORD` (at least 12 characters), then running
   `npm run db:seed:admin`. Do not run `npm run db:seed` against production.
5. In Vercel, open **Deployments**, choose the latest commit on the production
   branch, and select **Redeploy**. Check the build log for the generated
   Prisma Client and successful Next.js build.

Mentor registration and admin approval are available. Mentor booking requests
and the mentor-side student directory remain for a later phase.
